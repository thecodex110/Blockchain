# SHA-256

A hash maps any input to a 32-byte fingerprint. Flip one input bit → about **half** the output bits flip (**avalanche effect**), so data can't change without its fingerprint changing.

## Implementation — `crypto/hashing.py`
`BitLevelSHA256` follows FIPS 180-4 step by step, using 32-bit word helpers:
- `rotr32`, `shr32`, `add32` (mod 2³²)
- gates: `ch_gate`, `maj_gate`, `big_sigma0/1` (Σ), `small_sigma0/1` (σ)
- `pad_message` → 512-bit chunks → 64-word schedule → 64 compression rounds
- `compress_chunk_with_trace` records `RoundStateSnapshot`s (a–h per round) for teaching
- `analyze_avalanche(a, b)` → `AvalancheReport` (Hamming distance, % bits flipped)

## Fast backend — `crypto/fast_hash.py`
`HashlibSHA256(BitLevelSHA256)` overrides only `hash_bytes` with `hashlib.sha256`. Output is bit-identical (checked by `test_phase11_fast_hash`). Speeds: from-scratch ≈ 1k hashes/s; fast ≈ 250k–600k/s. Enabled with `--fast-hash` (terminal) and by default in the web bridge (`--bit-level-hash` to switch back).

## Where hashes are used
- Address = `SHA-256(public key bytes)` → [[Number Theory and RSA]]
- `tx_id = SHA-256(tx bytes)` → [[Transactions]]
- Merkle leaves/nodes → [[Merkle Tree]]
- Block hash = `SHA-256(88-byte header)` → [[Block and Header]], [[Proof-of-Work]]
- `.bclt` seal → [[Persistence]]
